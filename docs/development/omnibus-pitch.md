# Omnibus: задачи агента и как это продавать

> Вывод из [omnibus-spec.md](omnibus-spec.md) и [omnibus-architecture.md](omnibus-architecture.md) v1.0 (инструменты `desktop.tree` / `journal_query` / `pkg_install` / `pkg_remove` / `doctor` / `capabilities()` и др. — §5 архитектуры; ядро + сменные OS-адаптеры за SPI), внешние числа проверены ресёрчем от 09.10.2026.

## Часть 1. Что агент реально сможет делать

Ключ к пониманию: MCP превращает каждую задачу в комбинацию **дешёвого семантического чтения** и **типизированной записи**. Это радикально меняет экономику агента: чтение a11y-дерева стоит ~4k токенов и 50–200 мс против ~50k токенов и 3–8 с на скриншот, а надёжность выше на 12–17 п.п. ([замеры](https://prophetchrome.com/blog/accessibility-tree-vs-screenshots-browser-ai), [разбор](https://fde10x.com/alternative/build/accessibility-tree-vs-screenshots-production-agents)). Значит, агенту не нужна vision-модель на каждый шаг — компактных типизированных данных хватает даже локальной модели. Какой контур выбрать (локальный или облачный) — решает юзер выбором агента: сам omnibusd не делает ни одного модельного вызова.

### Кластер A — Диагностика и починка системы (`system` + `wiki`)

| Задача | Путь агента | Раньше |
|---|---|---|
| «Ноутбук не проснулся после сна» | `journal_query` (пред. загрузка — при `journal.persistent`: persistent на свежих установках — M0, табл. 1; на машинах, пробеченных volatile, — после opt-in через doctor) → `wiki_search` → вердикт + план фикса | 30–60 мин гуглежа по логам |
| «После обновления пропал звук/графика» | журнал + `pkg_list` / `pkg_info` (свежие транзакции) + вики → `svc_start` / `svc_stop` / `pkg_install` по гранту, выданному при настройке | частичный откат наощупь |
| «Приложение X падает при старте» | журнал ОС (journald или unified log) + core-метаданные + known-issues из базы знаний | чтение issue-трекеров вручную |
| Проактивный страж | агент следит за юнитами, чинит известные сбои по базе знаний (дистро-доки), эскалирует только нестандартное | крон-скрипты, которые никто не поддерживает |

Продающая формулировка кластера: **агент работает с фактами из журнала, а не с догадками LLM**.

### Кластер B — Рабочий стол как API (`desktop`: `desktop.tree` / `desktop.element` / `desktop.set_value` / `desktop.invoke` / `clip_*`)

- **Заполнение форм из локальных файлов** (анкеты, заявки, декларации): `fs_read` → `desktop.tree` → `desktop.set_value` → `desktop.invoke`. GUI-приложение становится таким же адресуемым, как REST.
- **Массовые правки в приложениях без их API**: переименовать 200 тегов, прогнать плейлист, обновить шаблоны — без pyautogo-хаков, которые ломаются о HiDPI и раскладки (урок из prior art: `:` → `^` на ru-группе).
- **Чтение закрытых приложений**: дашборды, мессенджеры, GUI-клиенты без экспорта — `desktop.tree` read-only.
- **Пакетная настройка**: «тёмная тема + крупный шрифт во всём» — обход настроек по семантическому дереву вместо ручного ползания по dconf.
- **`clip_read` / `clip_write`** — канат данных между приложениями без рук.
- На macOS тот же кластер работает через AX API — семантика инструментов не меняется, меняется адаптер.

### Кластер C — Файлы в скоупах (`files`)

- «Что за счёт валяется в Downloads? Разложи Documents по смыслу» — `fs_read` грантированных скоупов, перемещение через `fs_write`.
- «Найди все договоры с NDA и выпиши сроки» — юридическая выборка без облачного парсера: сервер не делает модельных вызовов, разбор делает ваш агент; выберете локальный контур — данные не покидают машину.
- Скоупы — это права, а не конвенция: на Linux чтение $HOME по умолчанию, запись — только по гранту; на macOS — TCC-гранты (за пределами пользовательских папок — Full Disk Access).

### Кластер D — База знаний как план действий (`wiki`: ArchWiki на Arch/Manjaro; дистро-доки и kb-guides на остальных)

- «Настрой как в вики»: свежая машина → агент читает статью (Hyprland, fstrim, btrfs) и **исполняет её с проверкой результата**, а не оставляет вас с открытой вкладкой.
- Онбординг под задачу: «сделай машину под Flutter-разработку» = база знаний + `pkg_install` / `pkg_remove` (pacman/brew/apt/dnf — что на машине) + верификация.
- Самозагрузка: `doctor` — первый сценарий агента в жизни — находит недостающие предпосылки Omnibus (a11y, порталы, персистентность журнала, TCC-гранты) и приносит готовую команду; изменения исполняете вы — агент не чинит систему сам. Догфудинг как онбординг.

### Кластер E — Композиты (то, за что платят)

- **Утренний брифинг**: журнал за ночь + почта/мессенджер (`desktop` read) → сводка в `notify`.
- **Watch-сценарии**: следи за сервисом X, при сбое — фикс по базе знаний, сообщение человеку только если не смог.
- **Headless GUI-тесты в CI**: `desktop.tree` + `desktop.invoke` работают без дисплея (M0-тест на Xvfb = сразу фича для разработчиков).

### Честные границы (продаём как фичи)

Не обходит права (скоупы); CLI/API приложения всегда лучше семантики; часть Electron-приложений требует явного включения a11y; генерация контента — работа модели, не ОС. Плюс честность по платформам:

- **Откат обновлений обещается только там, где есть `pkg.undo`**: alpm (downgrade из кэша) и dnf (transactional); **у apt нет транзакционного undo** — инструмент на Debian/Ubuntu/Mint честно не обещает откат.
- **Диагностика прошлых загрузок — только при персистентном журнале**: Arch — из коробки; Ubuntu/Mint/Debian/Fedora — persistent на свежих установках (M0, табл. 1); на машинах с volatile-конфигом — opt-in через doctor (prev_boot появляется с первой перезагрузкой после включения — читаем факт прошлых загрузок, а не конфигурацию).
- **Сеть — read-only**: NM read-only «когда есть» (за netplan на Ubuntu Server его нет), сетевые write-действия вне v1.
- **Скриншот на Linux — read без нашего гейта**: Wayland защищает портал DE, X11 — системного гейта не имеет (принятый риск v1); на macOS — TCC.
- **macOS**: права TCC выдаёт человек через GUI (Accessibility, Screen Recording с ежемесячным re-grant в 15+, Automation, Full Disk Access); программной выдачи нет (кроме MDM/PPPC) — `doctor` ведёт через визард.
- **Version floors**: systemd ≥ 252 (bullseye = 247 — ниже пола, там T3), macOS ≥ 14. Ниже пола адаптер не активируется — инструменты честно скрыты.

**Матрица поддержки v1** (tier = уровень гарантий и тестирования; полная — §6 архитектуры):

| Платформа | Tier | Что обещаем |
|---|---|---|
| Arch | **T1** | полный контракт, read+write, prev_boot из коробки, полный CI |
| Manjaro | **T1** | контракт T1 + своя тестовая матрица (mhwd, pamac, задержанные репы) |
| Debian trixie / bookworm / bullseye | **T2 / T2 / T3** | чтение + безопасная запись; apt — без undo; bookworm — systemd на полу; bullseye ниже floor |
| Ubuntu LTS | **T2** | чтение + безопасная запись; журнал — opt-in через doctor |
| Mint | **T2** | как Ubuntu LTS, X11-дефолт |
| Fedora | **T2** | как Ubuntu, плюс dnf transactional undo (виден в `capabilities()`) |
| macOS (адаптеры ax / unifiedlog / launchd / brew) | **T2** | вторая цель после победы на Arch; всё через TCC-гранты |

Спорные случаи всегда решает `capabilities()` — машинная правда конкретной машины, а не маркетинговая категория.

## Часть 2. Как продать

### Позиционирование

> **Omnibus — это API вашей системы.** Агенты видят её семантически — сервисы, журнал, окна, файлы, базу знаний — и действуют типизированно, а не тыкают по скриншотам. На Arch, Debian/Ubuntu/Mint/Fedora и macOS контракт один — меняются только адаптеры, о которых агенту знать не нужно: `capabilities()` говорит, что умеет эта машина.

Taglines: **«Semantics, not pixels»** · «Твоя система получила REPL» · «ОС, которую можно спросить».

### Три боли → три обещания

| Боль | Обещание |
|---|---|
| Рутина съедает вечера (диагностика, настройка) | «Минута вместо вечера» — и это демонстрируется, не обещается |
| Страх computer-use агента с полными правами | Read-only по умолчанию, типизированные записи, полный аудит: каждое действие — structured-событие в журнале вашей ОС (journald или unified log — приёмник сменный, схема едина) |
| «Куда уйдут мои данные?» | Внутри omnibusd ноль модельных вызовов: сервер не отправляет данные ни в какой LLM; локальность контура определяете вы выбором агента |

### Killer demos (по 30 секунд, по одному на сегмент)

1. **«Диагноз за минуту»**: ломаем юнит на камеру → агент: `journal_query` → причина → патч → `svc_start` по гранту, выданному вами при настройке.
2. **«Формы»**: визовая анкета заполняется из ~/Documents (`fs_read` → `desktop.set_value`) за 20 секунд.
3. **«После обновления»**: откат обновления там, где обещано (`pkg.undo`: alpm — downgrade из кэша, dnf — transactional); на apt демо честно показывает деградацию «журнал + план ручного фикса».
4. **«С нуля»**: пустая VM → рабочий стол под задачу, собранный агентом по базе знаний платформы.

### Сообщения по сегментам

| Сегмент | Сообщение |
|---|---|
| Arch-энтузиасты | «Ещё один клиент твоей системы — но на естественном языке и с семантическим зрением. Локальный бинарник без единого модельного вызова, всё в журнале, ничего нового в системе не тащит» |
| Разработчики | «MCP-native: экосистема уже на 12k+ серверов и ~97M месячных загрузок SDK ([статистика](https://ooty.io/blog/state-of-mcp-ecosystem-2026)), ваш Claude Code/Cursor/goose умеет из коробки — подключение одной строкой. Бонус: headless GUI-тесты» |
| Ubuntu / Mint / Fedora / Debian-пользователи | «Полное чтение + безопасная запись, честные границы — `capabilities()` покажет, что умеет именно ваша машина, ничего не обещает молча» |
| macOS-пользователи | «Тот же Omnibus на вашем Mac: AX API вместо AT-SPI, unified log вместо journald, brew вместо pacman — контракт тот же, права выдаёте вы (TCC), облако — только по вашему решению» |
| A11y-сообщество (союзники!) | «Агенты = новые массовые пользователи a11y-деревьев» — win-win сюжет для GNOME/KDE-конф; тезис подтверждён и в науке ([arXiv о стандартизации a11y через MCP](https://arxiv.org/html/2608.24898v1)) |

### Trust-контракт как главный дифференциатор

Продаём **проверяемость, а не ограничения**: «Агент, которому можно доверять, потому что каждое право — в манифесте скоупов, каждая запись — типизированная, каждое действие — structured-событие в журнале вашей ОС (journald / unified log / file-fallback — приёмник сменный, схема едина)». Это антипод cloud computer-use, где юзер не видит ни того, что агент «увидел», ни что сделал.

### Каналы и beachhead (по Муру)

1. **AUR** — арчеводы там живут; PKGBUILD уже в M0 (Arch T1 — beachhead).
2. **Show HN** + r/archlinux — разбор архитектуры, не маркетинг.
3. Phoronix/Hackaday — технические статьи; доклады на a11y-треках GNOME/KDE.
4. **Homebrew** — канал macOS T2 (formula в M3, с подписью и нотаризацией).
5. Дистро-репозитории Debian/Ubuntu/Fedora — после стабилизации T2-гарантий; NixOS и прочие — community-сборки через T3-путь (сборка есть, `capabilities()` отчитывается честно, гарантий нет).

### Метрики

- **TTFM < 5 минут**: от установки штатным пакетным менеджером платформы (pacman/brew/apt/dnf) до первой выполненной задачи (`doctor` + одна строка в конфиг MCP-клиента).
- **North star**: успешные агентные задачи в неделю.
- Retention D30, % задач без ручного вмешательства.

### Чего не делать

Не продавать «AI ОС» в лоб (усталость от buzzword) — продавать решённые задачи. Никакой обязательной телеметрии (для Linux-аудитории смертельно). Не обещать «заменит всё». Не обещать универсальный откат обновлений (только там, где есть `pkg.undo`). Не прятать скоупы/аудит — они и есть продукт.

### Elevator pitch (готовый абзац)

> Omnibus добавляет вашей системе то, что у неё уже почти есть: семантический API. Один бинарник (omnibusd) экспортирует сервисы, журнал, рабочий стол, файлы и базу знаний как MCP-инструменты — поверх сменных адаптеров: Arch (T1) с alpm и персистентным journald, Debian/Ubuntu/Mint/Fedora (T2) с apt/dnf, macOS (T2, ≥ 14) с AX, unified log и launchd. Любой ваш агент (Claude Code, goose, свой) начинает диагностировать сбои по журналам, заполнять формы в GUI, раскладывать документы и настраивать машину по базе знаний — сервер без единого модельного вызова, типизированно, с аудитом в журнале ОС; `capabilities()` честно сообщает, что умеет именно эта машина, а что скрыто. Не «ОС с ИИ», а ОС, которой наконец можно пользоваться агентом — безопасно.

**Суть продажи в одной фразе**: мы продаём не MCP-сервер, а минуты жизни и спокойствие — первый агент, которому не страшно дать клавиатуру, потому что он в неё не тычет, а вызывает методы.
